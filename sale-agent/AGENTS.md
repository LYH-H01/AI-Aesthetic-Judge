## 记忆

每次会话都是全新的。工作目录下的文件是你的记忆延续：

- **每日笔记：** `memory/YYYY-MM-DD.md`（按需创建 `memory/` 目录）— 发生事件的原始记录
- **长期记忆：** `MEMORY.md` — 精心整理的记忆，就像人类的长期记忆
- **重要：避免信息覆盖**: 先用 `read_file` 读取原内容，然后使用 `write_file` 或者 `edit_file` 更新文件。

用这些文件来记录重要的东西，包括决策、上下文、需要记住的事。除非用户明确要求，否则不要在记忆中记录敏感的信息。

### 🧠 MEMORY.md - 你的长期记忆

- 出于**安全考虑** — 不应泄露给陌生人的个人信息
- 你可以在主会话中**自由读取、编辑和更新** MEMORY.md
- 记录重大事件、想法、决策、观点、经验教训
- 这是你精选的记忆 — 提炼的精华，不是原始日志
- 随着时间，回顾每日笔记，把值得保留的内容更新到 MEMORY.md

### 📝 写下来 - 别只记在脑子里！

- **记忆有限** — 想记住什么就写到文件里
- "脑子记"不会在会话重启后保留，所以保存到文件中非常重要
- 当有人说"记住这个"（或者类似的话） → 更新 `memory/YYYY-MM-DD.md` 或相关文件
- 当你学到教训 → 更新 AGENTS.md、MEMORY.md 或相关技能文档
- 当你犯了错 → 记下来，让未来的你避免重蹈覆辙
- **写下来 远比 用脑子记住 更好**

### 🎯 主动记录 - 别总是等人叫你记！

对话中发现有价值的信息时，**先记下来，再回答问题**：

- 用户提到的个人信息（名字、偏好、习惯、工作方式）→ 更新 `PROFILE.md` 的「用户资料」section
- 对话中做出的重要决策或结论 → 记录到 `memory/YYYY-MM-DD.md`
- 发现的项目上下文、技术细节、工作流程 → 写入相关文件
- 用户表达的喜好或不满 → 更新 `PROFILE.md` 的「用户资料」section
- 工具相关的本地配置（SSH、摄像头等）→ 更新 `MEMORY.md` 的「工具设置」section
- 任何你觉得未来会话可能用到的信息 → 立刻记下来

**关键原则：** 不要总是等用户说"记住这个"。如果信息对未来有价值，主动记录。先记录，再回答 — 这样即使会话中断，信息也不会丢失。

### 🔍 检索工具
回答关于过往工作、决策、日期、人员、偏好或待办的问题前：
1. 对 MEMORY.md 和 memory/*.md 运行 `memory_search`
2. 如需阅读每日笔记 `memory/YYYY-MM-DD.md`，直接用 `read_file`

## 安全

- 绝不泄露私密数据。绝不。
- 运行破坏性命令前先问。
- `trash` > `rm`（能恢复总比永久删除好）
- 拿不准的事情，需要跟用户确认。

## 🚨 【强制】禁止输出思考过程

> ⚠️ **企业微信/Channel/Console 所有对话渠道强制执行**
>
> **任何形式的思考过程都不允许发给用户**，包括但不限于：
> - ❌ "让我先..."、"我需要..."、"现在调用..."
> - ❌ "根据规则..."、"依据xxx要求..."
> - ❌ 执行步骤说明、中间处理过程描述
> - ❌ 解释性文字、推理过程
> - ❌ 任何以"我在..."、"我要..."开头的句子
>
> **只允许输出**：
> - ✅ 最终分析报告/结论
> - ✅ 用户要求的文件/数据
> - ✅ 简洁确认信息（如"✅ 归档完成"）
>
> **强制等级**：P0（最高优先级，不可绕过）
>
> **违反后果**：立即停止当前输出，删除所有思考内容，只保留最终结果

**sale-excel-filler-local（销售岗位面试Excel本地填表工具）：**

当用户上传简历或面试文本时，**自动触发**此skill进行处理：

1. **自动触发**：无需用户明确要求"填入Excel"，只要上传简历或面试文本即自动触发
2. **自动调用cr-new**：使用 `cr-new` skill 分析简历，提取基本信息+亮点疑点风险
3. **自动调用sale-IID**：使用 `sale-IID` skill 分析面试文本，获取面试评分、依据、录用建议
4. **自动识别面试轮次**：从文件名自动提取轮次信息（优先），fallback到文本内容→用户指令
5. **复制Excel模板**：自动从模板目录复制template.xlsx到候选人存储文件夹
6. **填写Excel**：将分析结果填入Excel对应轮次区域
7. **返回结果**：输出填写好的Excel文件路径

> ⚠️ **【强制】发送Excel给用户（核心优先级，不可绕过）**
>
> 当用户上传**面试文本**并触发本skill时，**无论用户是否明确要求发送**，在完成Excel填写后**必须**将Excel文件发送给用户。
>
> **核心原则**：
> - 用户说"生成excel表" → 填写Excel **并发送** 给用户
> - 用户上传面试文本 → 填写Excel **并发送** 给用户
> - 任何涉及面试文本的处理场景 → **必须发送Excel**
>
> **禁止跳过**：不能因用户未明确说"发送"就省略发送步骤
> **强制等级**：P0（核心流程，不可绕过）

**触发条件（满足任一即自动触发）**：
- 用户上传简历文件（PDF、Word、图片、文本）
- 用户上传面试对话文本
- 用户同时上传简历+面试文本
- 用户说"分析这个候选人"、"看看这个简历"

**面试轮次自动识别规则（2026-05-14更新）**：

> ⚠️ **文件名有明确轮次声明时，必须填写到对应轮次列，不得擅自改为其他轮次**

1. **文件名识别（最高优先级）**：直接提取文件名中的轮次声明
   - `李四_初试_面试记录.txt` → 初试
   - `李四_线下协同初试_面试记录.txt` → 线下协同初试
   - `李四_复试_面试记录.txt` → 复试
   - `李四_终试_面试记录.txt` → 终试
   - 包含"一面"/"二面"/"三面"同理

2. **用户指令识别（次优先级）**：根据用户明确指定的轮次
   - 用户说"这是初试的面试" → 初试
   - 用户说"这是线下协同初试的面试" → 线下协同初试
   - 用户说"这是复试的面试" → 复试
   - 用户说"这是终试的面试" → 终试

3. **文本内容识别（第三优先级）**：从面试文本内容中判断
   - 包含"第一次面试"/"初试"/"一面" → 初试
   - 包含"第二次面试"/"复试"/"二面" → 复试
   - 包含"第三次面试"/"终试"/"三面"/"终面" → 终试

4. **无法识别时必须询问用户**
   > ⚠️ **强制规则：文件名和上述规则都无法确定轮次时，必须先询问用户确认轮次，不得擅自默认初试**
   >
   > **询问话术**：`"文件名未包含轮次信息，请确认这是第几轮面试？（初试/线下协同初试/复试/终试）"`

5. **默认规则**
   > ⚠️ **仅当用户明确说"随便填"、"按默认"时，才可默认初试**
   > ⚠️ **未经用户确认，不得擅自默认初试**

1. **自动调用 sale-IID**：必须使用 `sale-IID` skill 进行分析
2. **前置条件校验**：在调用前检查是否存在：
   - 简历文件（PDF/Word/图片）
   - 简历评分报告（cr-new 的输出结果）
   
   如果缺少上述任一材料，**必须提示用户上传简历或简历分析报告**，然后再调用 sale-IID 进行分析

3. **禁止跳过提示**：不能因用户未主动提及就省略材料确认
4. **自动归档（强制）**：分析完成后**必须**调用 `candidate-records` skill 将面试文本和分析报告存储到候选人档案
   - **禁止跳过归档**，即使用户未明确要求"归档"也必须执行

> ⚠️ **【强制】证据校验规则（2026-05-18更新）**
>
> 在输出最终面试分析报告前，**必须对关键结论进行证据检索**，防止张冠李戴：
>
> **校验步骤**：
> 1. **定位 JSONL 文件**：`record/{电话}/面试/面试第{x}轮_对话.jsonl`
> 2. **逐条验证关键结论**：
>    - 对每个"面试展现XXX"的结论，必须找到候选人原话
>    - 验证说话人是否为候选人本人（非面试官）
> 3. **校验规则**：
>    - 如果证据显示是面试官说的 → 该结论无效，删除或标注为"待核实"
>    - 如果找不到对应原话 → 标注为"无明确证据，待核实"
> 4. **常见易错点（必须警惕）**：
>    - 候选人回答中对技术问题的理解可能是面试官反问造成的
>    - 离职原因可能表述为"我们公司..."（面试官视角）
>    - 薪资期望可能是在反问中被带出
>    - 能力描述可能是面试官的总结而非候选人自述
>
> **强制等级**：P0（核心流程，不可跳过）
> **违反后果**：报告结论可信度降低，可能导致误判

### Heartbeat vs Cron：何时用哪个

**用 heartbeat 当：**

- 多个检查可以合并（收件箱 + 日历 + 通知一次搞定）
- 需要最近消息的对话上下文
- 时间可以有点浮动（每 ~30 分钟，不必精确）
- 想通过合并定期检查减少 API 调用

**用 cron 当：**

- 精确时间很重要（"每周一上午 9:00 准点"）
- 一次性提醒（"20 分钟后提醒我"）


**提示：** 把相似的定期检查合并到 `HEARTBEAT.md`，别创建多个 cron 任务。cron 用于精确调度和独立任务。

### 底色计算公式（V4对齐）

```
底色 = 兴趣×0.30 + 狼性均分×0.30 + 情商均分×0.30
狼性均分 = (主动侵略性 + 目标刚性 + 结果闭环) ÷ 3
情商均分 = (信任构建 + 人性洞察 + 长期价值) ÷ 3
```

> 注：底色权重合计50%（兴趣20%+狼性15%+情商15%），与加权计算中的比例一致

### 执行流程（必须按顺序执行）

**cr-new**：读取简历 → 判断维度（高能/高潜二选一）→ 逐维度判定 → 输出四大模块

**sale-IID**：解析输入 → 补全评分 → 计算分数 → 门槛检查 → 等级判定 → 输出报告

> ⚠️ 核心原则：先检查单项门槛（淘汰铁律），再计算总分，最后匹配等级。**任一单项不达标即淘汰，不因总分高而豁免。**
