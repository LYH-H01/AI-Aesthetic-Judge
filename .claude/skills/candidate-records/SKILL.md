# candidate-records — 候选人档案管理（性能优化版）

## 功能定位

以候选人的**电话号码**作为唯一标识符，建立和管理候选人档案文件夹。
支持以下操作：
1. **简历归档**：存储简历文件 + 可选调用简历分析 skill 生成报告
2. **面试归档**：存储面试文本 + 可选调用面试分析 skill 生成报告（支持多轮面试）
3. **快速模式**：只归档文件，跳过分析skill调用（大幅提升速度）
4. **批量归档**：支持同时归档多个简历/面试文件

## 文件夹结构

```
{根目录}/
└── record/
    └── {电话号码}/
        ├── 简历/
        │   ├── 原始简历.{原文件扩展名}
        │   └── 简历分析报告.md（可选）
        └── 面试/
            ├── 面试第{1,2,3...}轮_对话.jsonl
            └── 面试第{1,2,3...}轮_分析报告.md（可选）
```

**根目录**：智能体工作目录根目录下的 `record` 文件夹

## 输入要求

用户必须提供以下信息：

| 信息 | 说明 | 来源 |
|------|------|------|
| 电话号码 | 候选人的手机号，作为唯一ID | 用户明确告知 |
| 岗位类型 | 简历/面试所属岗位类型 | 用户明确告知，或从内容推断 |
| 简历文件 | 需归档的简历（PDF/Word/文本） | 用户上传或提供路径 |
| 面试文本 | 需归档的面试对话文本 | 用户上传或提供 |
| 面试轮次 | 第几轮面试（用户明确告知，否则自动递增） | 用户告知或自动检测 |
| 快速模式 | 是否跳过分析skill调用 | 用户明确告知"快速"时启用 |

## 性能优化特性

### 快速模式

当用户明确说"快速"、"只归档"、"不用分析"时启用：
- **跳过分析skill调用**，只保存原始文件
- 速度提升：省去 LLMs 调用时间（通常 5-15 秒）
- 用户可后续手动调用分析skill

### 高效文件操作

- 使用 **Bash cp 命令**直接复制文件，而非 Read+Write 两次操作
- 大文件（>1MB）直接使用文件系统复制，避免内存开销

### 批量归档

支持一次归档多个文件：
- "归档这三个简历" → 批量处理
- 每个文件独立调用分析skill（如需）

## 岗位类型与对应 Skill

| 岗位类型 | 简历分析 Skill | 面试分析 Skill |
|----------|---------------|---------------|
| 交付 | del-cr | del-IID |
| 研发/开发 | dev-cr | dev-IID |
| 销售 | cr-new | sale-IID |
| 其他/未知 | cr-new | 提示无法识别 |

## 执行流程

### 步骤 1：识别岗位类型和模式

根据用户输入识别：
- **快速模式**：用户明确告知"快速"、"只归档"、"不用分析"时启用
- **岗位类型**：
  - 用户明确告知 → 使用用户告知的类型
  - 用户未告知 → 从内容中推断
    - 包含 Java、Python、前端、算法等技术词汇 → 研发
    - 包含交付、项目管理、客户对接等词汇 → 交付
    - 包含销售���业绩、客户等词汇 → 销售

### 步骤 2：确定电话号码并创建根文件夹

1. 从用户输入中提取电话号码（纯数字格式，如 `13812345678`）
2. 清理电话号码（去除 +86、-、空格等）
3. 创建根目录：`{项目根目录}/record/{电话号码}/`

> 使用 Bash mkdir -p 命令一次性创建完整目录结构

### 步骤 3：处理简历归档

若用户提供了**简历**：

1. **创建简历子文件夹**：`{电话}/简历/`
2. **保存原始简历**：
   - 使用 Bash cp 命令直接复制（高效）
   - 若用户提供文本内容 → 直接写入文件
3. **可选：调用分析skill**（快速模式时跳过）：
   - 交付岗位 → 调用 `del-cr`
   - 研发岗位 → 调用 `dev-cr`
   - 销售/其他 → 调用 `cr-new`
4. **保存分析报告**（如调用了skill）：保存为 `简历分析报告.md`

### 步骤 4：处理面试归档

若用户提供了**面试文本**：

1. **创建面试子文件夹**：`{电话}/面试/`
2. **确定面试轮次**：
   - 用户明确告知 "第x轮" → 使用用户告知的轮次
   - 用户未告知 → 检查已有面试文件夹，自动递增
3. **转换为 JSONL 格式**：
   - 使用 `references/jsonl-parser.py` 脚本转换
   - 命令：`python references/jsonl-parser.py <输入文件> <输出文件>`
   - 输入：原始面试文本.txt，输出：面试第{x}轮_对话.jsonl
4. **可选：调用分析skill**（快速模式时跳过）：
   - 交付岗位 → 调用 `del-IID`
   - 研发岗位 → 调用 `dev-IID`
   - 销售岗位 → 调用 `sale-IID`
5. **保存分析报告**（如调用了skill）：保存为 `面试第{x}轮_分析报告.md`

> **JSONL 格式说明**：每行一个 JSON 对象，包含 `姓名`、`时间戳`、`内容` 字段，便于后续 skill 精准检索证据

### 步骤 5：汇总反馈

向用户汇报：
- 创建的文件夹路径
- 已保存的文件列表
- 启用快速模式时，提示可后续手动调用分析skill

## 注意事项

1. **电话号码唯一性**：同一候选人的多次简历/面试必须存入同一电话号码文件夹
2. **文件覆盖**：若同名文件已存在，提示用户确认是否覆盖
3. **自动创建目录**：所有中间目录自动创建，使用 mkdir -p
4. **Skill 调用**：分析 skill 的输出必须保存为 .md 文件
5. **原始文件保留**：原始简历和面试文本必须保留，以备后续查阅
6. **快速模式**：用户说"快速"、"只归档"时自动启用，省去分析skill调用
