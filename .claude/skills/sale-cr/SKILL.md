根据黑白灰清单规则对简历筛选评估，输出结构化分析报告。

> **重要提示**：本 skill 执行时需要读取 `references/sale-cr-rules.md` 获取完整的黑白灰规则。

## 黑白灰分类体系

- **黑清单**：不符合基本要求，建议直接淘汰
- **灰清单**：部分条件符合，需要进一步评估或面试
- **白清单**：各项条件优秀，优先推荐

## 执行流程

### 第一步：提取简历信息

提取：教育背景（学校层次、专业、生源地、入学年龄、四六级）、个人信息（民族、年龄）、工作经历（公司IT/非IT、岗位销售/非销售、年限、每段时长、断档、资源、项目案例）。

支持格式：PDF、Word、直接粘贴文本。

### 第二步：加载规则文件

> **必须读取** `references/sale-cr-rules.md` 获取完整的黑白灰规则和学历判定规则。

### 第三步：选择维度（核心）

- 工作年限≥3年 **或** 年龄≥27岁 → **只分析「高能基础信息类」**，高潜类完全忽略不输出
- 否则 → **只分析「高潜基础信息类」**，高能类完全忽略不输出

### 第四步：逐维度判定

对照规则文件中对应的规则表，对选中维度逐一判定：

- 命中任意黑清单项 → **黑**
- 无黑清单，但有灰清单项 → **灰**
- 无黑灰清单项 → **白**
- 简历中无该维度信息 → **信息缺失**
- 维度不适用 → **不适用**（说明原因）

**一票否决**：高能类公司或岗位命中黑 → 直接淘汰；高潜类岗位命中黑 → 直接淘汰

**特殊规则**：资源维度全部白→白、任意黑→黑、其余→灰；任职情况黑清单条件为「或」关系。

### 第五步：输出报告

流式输出，不创建文件。严格按以下四大模块输出，禁止添加基本信息、禁止冗余内容、**只输出被选中维度的判定表**：


## 注意事项

1. 无法提取的信息标"信息缺失"，不影响其他维度判断
2. 海外院校默认归灰名单（高潜类）
3. 年龄计算：入学年龄 = 本科入学年份 - 出生年份
4. **禁止**同时输出高能和高潜两个判定表
5. **禁止**输出候选人基本信息模块
6. **禁止**生成JSON文件
7. 语句通顺、逻辑清晰，避免机器腔

## 强制归档规则（分析完成后必须执行）

> ⚠️ **核心优先级，不可跳过**
>
> cr-new 分析完成后，**必须自动调用 candidate-records 进行归档**。

### 归档执行流程

```
cr-new 分析完成
      │
      ▼
步骤1: 提取身份信息（电话+姓名）
      │
      ▼
步骤2: 查询候选人索引
      │
      ▼
     ┌───┴───┐
     │ 已存在？│
     └───┬───┘
      是 ↙  ↘ 否
    更新档案  新建档案
      │
      ▼
步骤3: 保存文件
      ├─ 原始简历 → record/{电话}/简历/原始简历.{扩展名}
      └─ 分析报告 → record/{电话}/简历/简历分析报告.md
      │
      ▼
步骤4: 记忆同步（强制）
      ├─ 候选人索引更新
      ├─ 每日笔记更新
      └─ MEMORY.md 更新（如有必要）
```

### 归档文件规范

| 文件类型 | 路径 |
|----------|------|
| 原始简历 | `record/{电话}/简历/原始简历.{扩展名}` |
| 分析报告 | `record/{电话}/简历/简历分析报告.md` |

### 禁止事项

- ❌ 禁止跳过归档步骤
- ❌ 禁止不保存原始简历文件
- ❌ 禁止不更新记忆系统

### 完整执行顺序

1. 读取简历内容
2. 执行 cr-new 分析
3. **输出分析报告**
4. **自动触发 candidate-records 归档**
5. 等待归档完成确认
