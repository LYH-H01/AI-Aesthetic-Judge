# dev-IID — 研发岗位面试综合评估

## 功能定位

接收两类核心输入：① dev-cr 简历筛选评分结果；② 面试语音转文本的完整对话记录。
将简历中无法判断的评分项（标注"需面试补充"的维度）通过面试内容补全评分，
对所有评分维度进行简历与面试的交叉验证，最终输出完整的评分体系、对比分析和录用建议。

评分维度和标准严格依据 `dev-cr-rubrics.md`文件

## 输入要求

用户需同时提供以下两类数据（缺一不可）：

### 输入一：简历识别/评分结果（必须）

来自 dev-cr skill 的输出，核心信息包括：
- 各评分维度现有分数（含标注"简历无法判断""需面试补充"的项）
- 简历黑白灰识别结论
- 简历整体评级（录用/合议/淘汰）
- 面试提点（亮点、疑点、风险点）

**缺失时的引导**：
- 若用户仅提供**面试文本**，提示：
  > "本 skill 需要简历评分结果作为输入。请提供 dev-cr 的简历分析报告（或原始简历文件路径），我将在此基础上进行面试综合评估。"
- 若用户提供了**原始简历文件**但无评分报告，可主动调用 dev-cr 生成报告后再继续。

### 输入二：面试语音转换文本（必须）

完整的面试对话实录，包含：
- 面试官提问内容
- 候选人回答内容
- 面试时间、面试轮次等元信息（如有）

处理原则：精准提取候选人的语言表达、逻辑思维、专业能力、过往经历细节、职业规划、软实力等表述，
忽略无关冗余话术（寒暄、重复、与评估无关的闲聊）。

## 执行流程

### 第一步：解析输入

1. **解析简历评分结果**
   - 提取各维度现有分数
   - 标记所有"简历无法判断""需面试补充"的评分维度
   - 记录简历黑白灰结论和整体评级

2. **解析面试文本**
   - 区分面试官提问与候选人回答
   - 按评估维度归类候选人回答中的有效信息
   - 提取关键表述（原话或核心意思提炼），作为评分依据

### 第二步：读取评分标准

读取 `研发简历&面试识别评分标准.md`（位于 `dev-cr` skill 目录下），获取：
- 各维度的分值区间与评分标准
- 岗位分类（T01~T04）及三板斧能力详解
- 各薪酬级别最低分数线与基准线
- 录用/合议/淘汰判定规则

### 第三步：补全与完善评分

对每一个评分维度执行以下逻辑：

1. **简历已有明确分数的维度**：保留原分，仅在面试中出现重大矛盾时标注，不轻易修改
2. **简历标注"无法判断/需面试补充"的维度**：
   - 在面试文本中查找对应依据
   - 若找到明确依据 → 按评分标准打分，标注"面试支撑"
   - 若面试未涉及 → 标注"面试未涉及，暂按{合理默认分}分计分，建议后续补充提问核实"
   - 合理默认分取该维度基准线分数（通常为80分），但需结合已有信息综合判断，不得随意给高分
3. **所有维度**：标注得分依据来源（简历支撑 / 面试支撑 / 两者结合）

### 第四步：简历与面试对比分析

对每一个评分维度进行精准对比，归入以下三类之一：

| 对比类别 | 判定条件 |
|----------|----------|
| 简历与面试一致 | 得分匹配，表述契合，无矛盾 |
| 面试优于简历 | 简历未体现的技能/能力，面试中明确展现并验证 |
| 面试低于简历 | 简历标注的技能/经历，面试中无法佐证或存在偏差 |

每个维度的对比需引用具体依据（简历原文 / 面试原话），不脱离原文凭空判断。

### 第五步：计算加权总分与录用建议

- 按评分标准中的权重公式计算加权总分
- 对照对应薪酬级别的最低分数线和基准线
- 结合黑白灰结论和对比分析结果
- 给出录用建议（优先录用 / 可录用 / 待考虑 / 不录用）

### 第六步：证据校验（关键）

> ⚠️ **必须执行，防止张冠李戴**
>
> 在输出最终报告前，必须回溯关键结论到 JSONL 文件验证说话人

1. **定位 JSONL 文件**：候选人档案中的 `面试/面试第{x}轮_对话.jsonl`
2. **校验关键结论**：
   - 对每个"面试展现XXX"的结论，必须找到候选人原话
   - 验证说话人是否为候选人本人（非面试官）
3. **校验规则**：
   - 如果证据显示是面试官说的 → 该结论无效，删除或标注为"待核实"
   - 如果找不到对应原话 → 标注为"无明确证据，待核实"

### 第七步：输出报告

按标准输出格式（见下文）生成完整报告。

## 输出格式

整体输出分为三个模块，结构化呈现，便于 HR 直接查看和前端展示解析。

**依据来源说明**：

```
|---------|---------|---------|---------|---------|

| 质量好 | 一致/面试优于/面试低于 | | | |
```

**对比分析要点**：
- **简历依据**：引用简历原文中的关键表述（≤30字）
- **面试依据**：引用面试文本中的关键表述或核心意思提炼（≤30字）
- **差异说明**：简要说明差异原因和影响（≤50字）
- 重点突出"简历未体现、面试补充"和"简历与面试不符"的核心点

### 模块三：综合评价

控制在 **100字以内**，包含以下要素：

```
**综合评价**：{候选人整体表现}。核心优势：{1~2个最突出点}。
存在不足：{1~2个最明显短板}。
**录用建议：{优先录用/可录用/待考虑/不录用}**。
```

语言要求：专业、客观，不夸大、不遗漏关键信息，可直接作为 HR 决策参考。

## 评分铁律（不可违反）

1. **所有评分必须有明确依据**——简历原文或面试文本原话/核心意思提炼，拒绝无依据打分
2. **面试文本中未涉及的维度**，不随意打分，按"合理默认分"处理并标注建议后续核实
3. **合理默认分**：取该维度的录用基准线分数（通常80分），若简历已有部分信息可适当上下浮动，但不得超出基准线±10分范围
4. **三板斧1~5级映射分值**：1级=60, 2级=65, 3级=75, 4级=85, 5级=95
5. **狼性小计**（满分100）= 主动侵略性(40) + 目标刚性(30) + 结果闭环(30)
6. **智商小计**（满分100）= 毕业院校(35) + 数学成绩(45) + 简化能力(20)
7. **加权总分（非单元岗位）**= 狼性小计×22.5% + 智商小计×27.5% + 打深井×25% + 简化×10% + 质量好×15%
8. **评级规则**：
   - 加权总分 ≥ 对应级别最低线 且 所有基准项达标 → 录用
   - A1-A3级总分60~70 → 合议
   - 黑白灰=黑 → 不录用
   - 其他未达线 → 待考虑

## 面试文本提取指引

从面试文本中按以下维度提取有效信息：

| 评分维度 | 面试中可提取的信息 | 典型面试问题线索 |
|---------|-----------------|---------------|
| 兴趣 | 对技术的热情程度、自学经历、业余技术项目 | "你平时会做什么技术项目？" |
| 主动侵略性 | 是否主动承担任务、自驱推进、破局经历 | "有没有从0到1的经历？" |
| 目标刚性 | 面对困难的态度、目标达成记录 | "遇到过最难的项目是什么？" |
| 结果闭环 | 项目收尾意识、成果量化能力 | "这个项目最终结果如何？" |
| 毕业院校 | 学历背景（通常简历已有） | — |
| 数学成绩 | 高考数学成绩、竞赛经历 | "高考数学多少分？" |
| 简化能力 | 表达清晰度、逻辑结构、问题拆解能力 | 贯穿全程的表达质量 |
| AI能力 | AI工具使用经验、AI赋能实践 | "平时用哪些AI工具？" |
| 打深井 | 技术深度、领域专精度 | "讲讲XX技术的底层原理" |
| 简化 | 技术方案简洁性、问题拆解思路 | "怎么设计XX系统？" |
| 质量好 | 质量意识、测试习惯、文档规范 | "怎么保证代码质量？" |

## 注意事项

- 本 skill 是 dev-cr 的下游环节，评分维度和标准必须与 dev-cr 保持一致
- 评分标准文件位于 `dev-cr` skill 目录：`研发简历&面试识别评分标准.md`
- 输出内容需可直接被 HR 智能体读取解析，不添加无关冗余内容
- 对比分析需精准对应简历和面试原文，避免模糊表述
- 若面试文本质量极差（严重缺失、噪声过多），在报告中标注并建议重新面试
