模块二：系统命令规则（2026-04-16）
`/jd list` 命令
功能：扫描`jd/`目录下的所有文件，提取元数据中的`name`和`description`字段，用于快速查看可用研发岗位JD。
执行规则
1. 扫描`jd/`目录下的所有文件（支持.md和其他格式），不遗漏任何JD文件。
2. 提取每个文件的YAML front matter元数据，精准获取`name`和`description`字段。
3. 以表格形式输出结果，不添加任何额外说明文字，保持简洁。
输出要求
- 只输出表格，不输出任何其他说明文字、过渡语句。

- 表格格式必须严格遵循Markdown表格语法，确保显示规范。

模块四：dev-cr技能核心规则（2026-04-14）
dev-cr技能用于研发岗位简历分析，需严格遵循以下规则，确保筛选精准、格式规范。
1. 7个维度全覆盖：必须分析全部7个维度（目标学校、目标公司、岗位、在职情况、工作地、年龄、籍贯），不遗漏任何一个核心维度。
2. 一票否决：任一维度命中黑清单，候选人直接淘汰，不进行其他维度额外评估。
3. 籍贯规则严格：
        
  - 黑清单：北京、天津、上海等高考难度较低地区，或新疆、西藏、云贵等政策倾斜地区
  - 白清单：河北、山东、山西、河南、江苏等高考难度较大的省份
  - 特殊说明：即使候选人其他维度优秀，籍贯命中黑清单仍直接淘汰，不放宽标准。
4. 输出格式：严格按照三大模块输出，不添加任何额外内容：
        
  - 逐维度分析
  - 结论（是否通过）
  - 面试官输入（仅通过时输出）
模块五：扫描件简历处理经验（2026-04-14）
针对扫描件、特殊编码等难以提取文本的研发简历，制定以下处理规则，确保筛选工作正常推进。
1. PDF提取问题：部分简历为扫描件或特殊编码，可能出现文本提取失败的情况，需灵活处理。
2. 信息缺失处理：
        
  - 尽可能从可识别文本中提取研发相关关键信息（如岗位、工作年限、技术栈等）。
  - 信息缺失的维度，明确标注“信息缺失”，不随意推测。
  - 基于已有信息进行初步评估，不因信息缺失直接淘汰。
3. 边缘通过判定：
       
  - 无黑清单命中，但多个维度信息缺失 → 判定为边缘通过。
  - 边缘通过候选人，需在面试中重点核实缺失信息，确认是否符合研发岗位要求。
4. 文件名分析：当文本提取困难时，可从简历文件名获取岗位类型信息（如“研发AI效能”“Java后端简历”），辅助岗位识别。

模块十六：候选人档案管理系统（2026-05-07新增）
背景
用户要求将简历/面试归档与记忆系统联动，实现智能档案管理。

【强制规则】分析简历后必须自动存储：每次分析完简历，都必须调用 candidate-records skill 进行归档存储，确保所有分析过的候选人都被记录。

candidate-records skill 配置
文件夹结构
```
{工作目录}/record/
└── {候选人标识（电话或姓名）}/
    ├── info.md                    # 候选人基本信息
    ├── 简历/
    │   ├── 原始简历.{扩展名}
    │   └── 简历分析报告.md
    └── 面试/
        ├── 面试第1轮_原始文本.txt
        ├── 面试第1轮_分析报告.md
        └── ...
```

身份识别优先级
1. 电话号码（最可靠，可直接定位档案）
2. 姓名（需遍历所有档案文件夹名匹配）

核心功能
1. 智能查询：自动检查 record/ 目录是否存在对应档案
2. 追加更新：已存在则智能追加（更新简历 / 增加面试轮次）
3. 自动关联：提交面试文本时自动关联已有简历档案
4. 记忆联动：每次操作强制记录到 memory/YYYY-MM-DD.md

决策逻辑表
| 输入情况 | 处理方式 |
|---------|----------|
| 电话已存在 | 直接追加更新 |
| 姓名匹配到档案 | 关联该档案 |
| 只有面试 + 已有简历 | 追加面试到对应档案 |
| 只有简历 + 已有面试 | 更新简历关联 |
| 全新候选人 | 创建新档案 |

执行流程（6步骤）
1. 提取身份信息（电话/姓名）
2. 查询档案是否存在（检查 record/ 目录）
3. 决策处理方式（新建/追加/关联）
4. 执行归档（保存原始文件 + 调用分析skill）
5. 记录到记忆系统（memory/YYYY-MM-DD.md）
6. 向用户反馈

info.md 内容模板
```markdown
# 候选人信息

- 电话: 13812345678
- 姓名: 张三
- 岗位: 研发
- 创建时间: 2026-05-07 14:30
- 更新时间: 2026-05-07 14:30
```

记忆记录格式
```markdown
## 📁 候选人档案操作 [2026-05-07 14:30]

- **操作类型**: {新建/追加简历/追加面试}
- **候选人**: {电话} / {姓名}
- **岗位**: {岗位类型}
- **归档内容**: {具体内容描述}
- **档案路径**: record/{标识}/
- **分析报告**: {有/无}
```

使用场景
- "归档这份简历，电话 13812345678"
- "归档这次面试记录，候选人姓李"
- "快速归档这份简历，不用分析"
