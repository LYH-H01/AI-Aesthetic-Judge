 **2020.12** **Oracle** **RAC** **实例针对问题进行调优**

> **背景描述：**
>
> 客户发邮件通知业务系统登录不了，一直在等待状态，cpu
> 居高不下，数据库处在挂起状态，无法正常运
>
> 行，需要处理使业务恢复正常工作。
>
> **过程描述：**
>
> 1\. 发现数据库没有 DOWN 机，通过 sql 查询视图 v\$locked_object 和
> v\$session，查到数据库中存在大 量的 TX
> 等待事件。断定是由于系统中存在着某个事务没 commit 或者
> rollback。导致数据库处在等待 的状态。
>
> 2\. TX 锁同城被称为事务锁，当一个事务开始时，执行 dml
> 操作会获取事务锁，事物结束才能释放，而且
>
> oracle 的行级锁是在数据块上获得的，只有排它锁。
>
> 3\. 通过 awr
> 报告以及相关视图等发现有个存储过程存在阻塞，其他操作都在等待该存储过程结束，从而产
>
> 生了大量的等待，通过 plsql 打开存储过程发现该存储过程没有 commit
> 动作，要知道如果存储过程中
>
> 未发现 commit 提交动作，那么显然多个会话执行时有行锁的风险，随后将其
> sql 通过 sid 提取出来，
>
> 对其阻塞的 sql 进行杀锁操作，数据库恢复正常并在该存储过程中添加 commit
> 动作。后来经核对，是
>
> 由于开发人员当时写存 储过程的时候忘记的 commit 动作。

> Yes，Slave_SQL_Running: Yes，主
